# Component catalog — Design History

The canonical UI-pattern catalog: how a design label resolves to one component with one set of guidance, and the rules that keep that resolution stable across generated consumer projections.

## Current state

- The catalog is a flat set of canonical patterns under `skills/ui-design-brain/patterns/`, one markdown file per pattern (currently 80).
- `patterns-manifest.json` is the single source of truth. Each entry carries `name`, `slug`, `aliases`, and `file`, with `slug == kebab(name) == filename`. Consumers resolve a design label to one canonical by exact string — `name`, then plain alias, then context alias — and treat an unresolved label as novel.
- Most aliases are plain strings. A few are context-scoped `{ name, context }` objects (Banner, CTA, Label, Stepper) that resolve to different canonicals by context; `index.md` mirrors them in a Context-scoped aliases table.
- `index.md` is the first-hop narrowing list; each pattern file holds a one-line definition, bidirectional cross-references, bounded product guidance, and common layouts.
- UI Design Brain owns canonical names, slugs, aliases, contextual disambiguation, and bounded product guidance. It does not own accessibility semantics, applicability, proof routes, or slug-to-accessibility mappings.
- Existing accessibility-adjacent bullets remain informative and non-normative during parity migration. Downstream pipelines must obtain normative obligations and mappings from an exact `@verndale/accessibility-standards` contract rather than infer them from this prose.
- Cross-references between confusable patterns are bidirectional prose pointers. Child modules (a Carousel's Slide, a Tabs' Tab / Tab panel, an Accordion's Accordion item) are named in prose but never aliased, so ba-cockpit child-spec smart-linking keeps treating them as novel.
- Visual variants (for example the tabs pill / underline / segmented styles) are an axis orthogonal to ARIA and never change the resolved canonical.
- Authoring structure and conventions live in `skills/_meta/` (authoring-only, never projected). Catalog integrity is enforced both by the generated `catalog-manifest.json` schema/digest contract and the manifest-to-pattern `catalogs` edges in `pnpm graph:check`.

- 2026-08-30 — Bounded this catalog to UI vocabulary and product-pattern guidance, retained accessibility-adjacent prose as explicitly non-normative until parity, and assigned normative semantics, applicability, evidence, and UI-pattern bindings to `accessibility-standards`. This preserves the catalog's valuable disambiguation without creating a second accessibility authority ([verndale/ui-design-brain issue #47](https://github.com/verndale/ui-design-brain/issues/47), [plan](../plans/2026-08-30-deterministic-ui-design-brain-projections.md), [journal](../journal/2026-08-30-deterministic-ui-design-brain-projections.md)).
- 2026-08-08 — Clarified the **Hero** ↔ **Alert** banner boundary (guidance, no catalog delta): a promotional band with an image, headline, and one or two CTAs is a **Hero** even when a project names it "message banner" or "CTA banner"; the **Alert** case is the dismissible page notification. Bidirectional cross-reference; no alias added, since a plain "Message banner → Hero" alias would misresolve Alert-style banners ([journal](../journal/2026-08-08-hero-promo-banner-vs-alert.md)).
- 2026-08-08 — Added the **Mega menu** pattern (79 → 80): a large, full-width disclosure panel dropped from a top-level nav item, presenting a site's sections as several columns of grouped links with its own disclosure/focus/motion contract — distinct from the compact **Navigation** bar, a single-column **Dropdown menu**, and the off-canvas **Drawer**; promoted on cross-client recurrence (two independent client retrospectives, one fingerprint-backed and one spec-backed). Added the consumer-evidenced aliases Header mega menu, Mega menu panel ([journal](../journal/2026-08-08-add-mega-menu-pattern.md)).
- 2026-08-08 — Added the **Media object** pattern (78 → 79): a full-width, two-column image↔text content band (a text block beside a single image/video, columns alternating down the page) — the OOCSS "media object" at section scale, distinct from the tile-in-grid **Card**, the page-top **Hero**, and the media-less **Section header**; minted on unusually broad intra-project recurrence (four initiatives, each with an approved functional spec). Added the consumer-evidenced alias Media block ([journal](../journal/2026-08-08-add-media-object-pattern.md)).
- 2026-08-06 — Added the **Logo bar** pattern (77 → 78): a full-width, non-interactive band of partner/customer/certification logos presented as social proof (often auto-scrolling, with a WCAG 2.2.2 pause/play control) — distinct from the continuously-scrolling text **Marquee** and from **Hero**/**Card**; promoted on two independent sources (an as-built build pack and an approved functional spec) within one retrospective. Added the plain aliases (Logo cloud, Logo wall, Logos bar, Partner logos) and the reciprocal Marquee → Logo bar cross-reference ([journal](../journal/2026-08-06-add-logo-bar-pattern.md)).
- 2026-08-06 — Added the consumer-evidenced **Testimonial** alias to **Quote** (77 → 77): a project's "Testimonial" label (a first-person quote with a portrait photo + author name/role attribution) that had resolved to novel — the "testimonial block with photo, quote, name, and title" layout Quote's guidance already claims; registered as a plain alias since it names the whole component, not a child part ([journal](../journal/2026-08-06-add-testimonial-alias-to-quote.md)).
- 2026-08-05 — Added the consumer-evidenced **Article hero** alias to **Masthead** (77 → 77): a project's "Article hero" label for the editorial article masthead (publish-date badge + title + tags) — the "compact article masthead" layout Masthead's guidance already claims; registered as Masthead's first alias, kept plain since the identify-vs-sell line already separates it from **Hero** ([journal](../journal/2026-08-05-add-article-hero-alias-to-masthead.md)).
- 2026-08-05 — Added the **Utility bar** pattern (76 → 77): a persistent, fixed-position cluster of global page utilities (scroll-to-top, help/chat launcher) that stays put across scroll — distinct from the in-flow **Button group** (which aliases Toolbar), promoted on two independent sources (a component registry entry and an approved functional spec) within one retrospective. Added the alias Floating utility bar and the reciprocal Button group → Utility bar cross-reference ([journal](../journal/2026-08-05-add-utility-bar-pattern.md)).
- 2026-08-05 — Added the **Comparison table** pattern (75 → 76): a feature/plan comparison matrix — entities as columns, a shared attribute set as rows, boolean cells, an optional recommended column, and a mobile column-selector — distinct from the arbitrary-data **Table** and a single-plan **Card**; promoted on two independent sources (a component registry entry and an approved functional spec) within one retrospective. Added the consumer-evidenced alias Features comparison table ([journal](../journal/2026-08-05-add-comparison-table-pattern.md)).
- 2026-08-05 — Added the **Search overlay** pattern (74 → 75): a full-screen search surface opened from a global trigger — input, quick links, and a recent-searches/suggestions results panel — with its own open/closed × idle/active state machine, distinct from the inline **Search input**, a plain **Modal**, and the inline-autosuggest **Combobox**; promoted on two independent sources (an as-built build pack and an approved functional spec) within one retrospective.
